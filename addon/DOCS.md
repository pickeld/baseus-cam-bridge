# Baseus Cam Bridge — Add-on documentation

This add-on logs in to the Baseus cloud with **your own account**, discovers
**your own cameras**, and republishes their live video on your Home Assistant
host as RTSP / HLS / WebRTC. Streams are pulled on demand, so battery cameras are
only contacted while something is watching.

## Configuration

| Option | Default | Description |
|---|---|---|
| `account` | – | Your Baseus Security app login (email or phone). |
| `password` | – | Your Baseus Security app password. |
| `region` | `AUTO` | `AUTO` tries US/EU/AU; or force `US` / `EU` / `AU`. |
| `country_code` | `1` | Phone country code used at login (e.g. `1`, `44`, `61`). |
| `include_offline` | `true` | Also create paths for currently-offline cameras. |
| `framerate` | `25` | Assumed input framerate for muxing. |
| `stream_quality` | `hd` | `hd` (main stream) or `sd` (sub stream — lighter, loads faster). |
| `always_on` | `false` | Keep every camera streaming from startup (instant load; best for mains-powered cameras). `false` = on-demand (battery friendly). |
| `start_timeout` | `60` | Seconds to wait for a camera's first frame before giving up. Raise if cameras wake slowly. |
| `close_after` | `30` | Seconds to keep a stream warm after the last viewer leaves. Higher = faster re-opens, more battery/bandwidth. Ignored when `always_on` is set. |

Example:

```yaml
account: you@example.com
password: your-baseus-password
region: AUTO
country_code: "1"
include_offline: true
framerate: 25
stream_quality: hd
always_on: false
start_timeout: 60
close_after: 30
```

### Tuning for reliability / faster loading

- **Streams slow to load / time out on first open:** cameras (especially battery
  ones) can take 10–20 s to wake. Keep `start_timeout` at 60 or higher.
- **"Gets stuck" / re-opens are slow:** raise `close_after` (e.g. `120`) so the
  stream stays warm between views, or enable `always_on` for mains-powered cameras.
- **Want the fastest possible open:** set `always_on: true`. Every camera streams
  continuously, so Home Assistant shows video instantly (higher battery/bandwidth use).
- **Weak Wi-Fi / choppy video:** set `stream_quality: sd` for the lighter sub-stream.

## Ports

The add-on uses **host networking**, so these ports are served directly on the
Home Assistant host:

| Port | Protocol | Use |
|---|---|---|
| 8554 | TCP | RTSP — `rtsp://homeassistant.local:8554/<camera>` |
| 8888 | TCP | HLS — `http://homeassistant.local:8888/<camera>/index.m3u8` |
| 8889 | TCP | WebRTC — `http://homeassistant.local:8889/<camera>` |
| 8189 | UDP | WebRTC ICE |

Host networking is required so the bridge can reach the cameras' P2P transport on
your LAN.

## Using with the HACS integration

Install the [Baseus Security integration](https://github.com/pickeld/baseus-home-assistant)
and set its **RTSP base URL** to `rtsp://homeassistant.local:8554` (the default).
The camera slugs are generated by the same code in both places, so they line up
automatically.

## Troubleshooting

- **"Set your Baseus account and password"** — fill in the Configuration tab.
- **No cameras found** — verify the account/password and try forcing `region`.
- **Stream won't open** — battery cameras take ~10–15 s to wake on first connect;
  confirm the camera is online in the Baseus app.
- **Logs** — the add-on **Log** tab shows discovery results and MediaMTX output.

## Security notes

- Credentials are provided via the add-on options and passed to the bridge as
  environment variables at runtime; they are not written to the image.
- Only the initial login + device-list call goes to the Baseus cloud (the same
  call the official app makes). Video stays on your LAN.
- Use this only with cameras you own or are authorized to manage.
